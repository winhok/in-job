# 微信服务号扫码登录集成

## 问题

登录页已经具备微信二维码展示和轮询界面，服务端也已创建空的微信模块，但二维码生成、微信事件回调、用户登录闭环和服务号菜单管理尚未实现，当前页面无法完成真实微信登录。

## 范围

- 通过微信公众号接口生成五分钟有效的带参临时二维码。
- 接收并校验微信服务器回调，处理关注、已关注用户扫码和菜单点击事件。
- 维护二维码状态，按 OpenID 查找或创建用户并签发系统 JWT。
- 提供二维码状态轮询接口，并完善前端刷新、过期、轮询和登录成功处理。
- 提供受保护的服务号菜单创建、查询和删除接口，以及菜单图片回复能力。
- 通过环境变量注入微信凭据、菜单地址和菜单图片路径，不提交敏感信息。

## 非目标

- 不代替用户在微信公众平台完成服务号认证、IP 白名单、回调 URL 或消息加密模式配置。
- 不在本地调用真实微信接口、创建或删除真实公众号菜单。
- 不实现另一套微信开放平台网站 OAuth 登录流程。
- 不把单进程内存状态扩展为 Redis 或多实例共享状态。
- 不把本地测试和构建结果视为线上扫码验收或生产发布证据。

## 受影响契约

- `POST /wechat/qrcode` 返回二维码地址、二维码 ID 和过期时间。
- `GET /wechat/check-qr-status?id=...` 返回等待、成功或过期状态；成功时携带用户与 JWT。
- `GET /wechat/validateToken` 校验微信服务器配置握手签名并原样返回 `echostr`。
- `POST /wechat/validateToken` 校验微信签名并接收 XML 事件，返回微信要求的 XML 或 `success`。
- `POST /wechat/create-menu`、`GET /wechat/get-menu`、`POST /wechat/delete-menu` 仅允许管理员 JWT 调用。
- 服务端新增 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`WECHAT_TOKEN` 等运行时配置，敏感值只存在于未跟踪的环境配置中。

## 风险

- 二维码状态存储在进程内存中，服务重启或多实例负载均衡会丢失或分裂登录状态。
- 微信回调、素材上传和菜单接口依赖公网域名、公众号权限、白名单和有效凭据。
- 菜单创建与删除会修改公众号远端状态，必须保持管理员鉴权且不能在本地验证阶段调用。
- 另一套网站 OAuth 方案会把 AppSecret 暴露给浏览器，本实现明确不采用该不安全契约。

## 验收标准

- 配置完整时，服务端能请求并缓存微信 access token，生成带唯一场景值的临时二维码。
- 合法签名的关注或扫码事件能将对应二维码更新为已确认，非法签名请求被拒绝。
- 已确认二维码只完成一次用户查找或创建，并返回与现有鉴权策略兼容的 JWT。
- 前端同一时间只维护一个倒计时和一个轮询任务，刷新与卸载会清理旧任务。
- 菜单管理接口具备管理员保护，菜单点击能返回合法文本或图片 XML。
- 相关服务单元测试、服务端构建、前端构建和 DeliveryGuard 检查通过，或明确记录环境阻塞。
