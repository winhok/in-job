# 异步评估报告技术设计

## 查询与类型识别

`InterviewService.getAnalysisReport` 先以 `resultId + userId` 查询简历押题结果，再查询模拟面试结果。简历押题报告只做格式转换和查看统计更新；模拟面试报告根据 `reportStatus` 决定返回、补触发生成或提示等待。

所有查询都绑定当前 JWT 用户。模拟面试返回对象采用显式字段映射，不暴露 `sessionState`、简历原文、用户标识、消费记录或数据库内部字段。

## 异步状态认领

生成任务先使用条件更新把当前用户的 `pending` 或 `failed` 记录原子更新为 `generating`。只有拿到更新后文档的调用方继续执行，其他并发调用直接返回。结束接口和查询接口都只负责触发，不等待模型完成。

```text
pending/failed --atomic claim--> generating --success--> completed
                                      |
                                      +--error-----> failed
```

## 评估生成

服务从持久化的 `qaList` 中筛选具有真实问题和非空回答的问答对。没有有效问答时直接写入固定低分报告。有有效问答时计算总题数、平均回答长度和短回答数量，将这些指标与职位、JD、简历快照和标准答案一并交给 `InterviewAIService`。

AI 服务使用专用提示词和 JSON 解析器，随后校验分数范围、数组字段、雷达维度和改进建议结构。只有通过校验的结果才能写入数据库。

## 错误边界

后台触发入口捕获并记录错误，生成方法负责将错误原因写入 `reportError` 并将状态更新为 `failed`。API 不等待后台任务，也不向客户端泄露模型错误堆栈。

## 验证边界

- 服务单元测试覆盖简历报告、所有权、并发认领、空回答、成功生成和失败重试。
- AI 服务单元测试覆盖提示词分支和结果校验。
- 服务端构建验证 Nest/TypeScript 结构。
- 真实 MongoDB、真实模型、浏览器轮询和生产恢复能力仍需独立验收。
