# 异步评估报告生成

## 问题

简历押题结果已经包含岗位匹配分析，模拟面试结果也已持久化问答记录，但当前缺少统一的报告查询入口，模拟面试结束后也不会生成结构化评估。前端因此无法用同一个结果 ID 查询两类报告，也无法区分报告生成中、已完成和失败状态。

## 范围

- 新增鉴权的统一报告查询接口，按结果 ID 识别简历押题或模拟面试结果。
- 将简历押题结果格式化为稳定的报告 DTO，并原子更新查看统计。
- 模拟面试结束后异步生成结构化评估，报告查询可补触发尚未开始或失败的任务。
- 为无有效回答的面试生成固定低分报告，避免无意义的模型调用。
- 新增鉴权的失败报告重新生成接口。
- 保存报告状态、生成时间和失败原因，并防止同一报告被并发重复生成。

## 非目标

- 不改造前端报告页面或历史记录页面。
- 不引入消息队列、分布式任务调度或跨进程锁。
- 不执行真实模型调用、生产部署或发布。
- 不把本地构建和单元测试视为正式验收证据。

## 受影响契约

- 新增 `GET /interview/analysis/report/:resultId`，只允许结果所属用户查询。
- 新增 `POST /interview/analysis/report/:resultId/regenerate`，只允许结果所属用户重试失败或待生成的模拟面试报告。
- 模拟面试报告在 `pending -> generating -> completed` 或 `failed` 状态之间流转。
- 报告尚未完成时，查询接口返回明确的“正在生成”错误；结果不存在或不属于当前用户时返回未找到。
- 简历押题报告返回 `ResumeQuizAnalysisDto`；模拟面试报告返回去除内部会话、用户标识和数据库字段后的结构化数据。

## 风险

- AI 输出可能缺字段、越界或不是预期结构，必须校验后才能持久化。
- 进程重启可能遗留 `generating` 状态；本切片通过显式失败重试处理，不承诺分布式任务恢复。
- 结束接口和查询接口可能同时触发生成，需要通过原子状态认领避免重复模型调用。
- 后台任务失败不能形成未处理的 Promise rejection，失败原因仍需写回结果记录。

## 验收标准

- 用户能通过自己的简历押题结果 ID 查询完整匹配报告，查看次数被原子递增。
- 用户不能查询或重新生成其他用户的报告。
- 模拟面试结束立即返回，后台报告任务独立执行。
- 同一模拟面试报告在并发触发时最多只有一个生成任务获得执行权。
- 无有效回答时不调用 AI，并保存已完成的低分报告。
- 有效回答会携带职位、简历、问答及回答质量指标调用 AI，并保存完整评估字段。
- AI 失败会保存 `failed` 状态和错误信息，重新生成接口可再次触发。
- 相关单元测试、服务端构建和 DeliveryGuard 检查通过。
